# 文件下载卡片

从 AgentCore 工具列表添加 `file_download`，将 `vision_capture` 右侧的“可下载文件”输出口连到下载卡片左侧的同名输入口。在下载卡片选择照片或视频，点击“查看文件并下载”。列表支持逐个下载及刷新；项目停止时也可使用。

历史列表来自磁盘，不依赖页面上的拍摄结果。删除文件后刷新列表即可移除；录制中的视频和空文件不列出。相机离线但 driver 仍能提供目录信息时，可以下载历史文件。目录尚未创建、未共享或 driver 不可达时，列表显示读取错误。

## 文件来源连线

连线继续保存在现有 `canvas_layout.connections`，使用 `format: file/reference`，两端的端口索引为 `files`。它绑定来源卡片的身份，不是 DDS 话题，不发布文件字节，不参与 DDS 话题推导、订阅或项目启动依赖。现有音视频、控制和 JSON 数据流不变。

首个来源适配器是 `vision_capture`：前端为它增加文件引用输出口，通过已有 `action: info` 读取 `photos_dir`、`videos_dir` 和 `active_recording.path`，再调用 `/api/file/list` 查询磁盘。视频列表读取后再次查询录制状态，排除正在写入的文件。该适配不改变 driver 的拍照、录制、取消行为。

下载经带鉴权的 `/api/file/download` 获取文件，浏览器保存到用户电脑。目录必须在 Agent Core 容器内可读；连线本身不会建立跨容器共享。当前 Bumi 的共享目录部署满足此前提。首版不包含压缩包批量下载、已删除文件恢复或 driver 异常退出后残留视频的完整性检查。

后续接入其他文件生成工具时，需要增加来源适配器，提供持久历史目录查询和未完成文件排除规则，再为该卡片开放文件输出口。不要把只有文件路径或动作编号的返回直接认定为可下载成品。

## 验收

- 未连接来源时提示连线，不调用拍摄或文件接口。
- 连接后列出历史照片、已完成视频；刷新页面仍能通过保存的连接查询。
- 删除文件后刷新列表；并发删除或下载鉴权失败时显示错误。
- 录制中及取消后的未完成视频不提供下载。
- 断开连线后不再查询来源；连接及下载均不触发拍照或录像。
- 原有拍照、录像、参数显隐、结果展示和普通数据连线保持原行为。

本地自动测试及模拟浏览器检查不代表实机验收；此变更不会自动部署到机器人。
