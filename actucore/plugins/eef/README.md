# eef · 机械臂末端控制

在画布上连接 `eef_state → eef → servo_eef`。`move_to` 直接设定选定手臂的工具中心点（TCP）位姿、夹爪开口，或同时设定两者。`move_by` 从最新实测状态平移或旋转 TCP，也可增减夹爪开口。`cancel` 将受控位姿或开口保持在实测值。

## 接线与消息

本卡从 `state/eef` 输入口接收实测状态，通过 `control/eef` 输出口发布绝对目标。下表为 TRON2 的话题与消息格式。

| 话题 | 消息 |
| --- | --- |
| `/limx_tron2/state/eef` | `motus.eef/1`，四字段为 `schema`、`frame`、`stamp_ms`、`eef`。时间戳是实测采样时间。 |
| `/limx_tron2/control/eef` | `motus.control/1`，`mode=eef_pose`、`dof=16`，`values` 存放完整绝对目标，`frame=base_Link`。 |

TRON2 的两个向量都按左 TCP 位姿、左夹爪开口、右 TCP 位姿、右夹爪开口排列。位姿为 `x, y, z, qx, qy, qz, qw`，位置和开口以米计。启动时画布从下游 `servo_eef.info()` 取得 `control_interface` 并传给本卡。卡片按描述符识别参考坐标系、每个 TCP 和夹爪的分组偏移、笛卡尔边界、夹爪行程和时效参数。单臂驱动可以只声明左臂或右臂的两个分组，共八个值。

`eef` 和 `autonomous_task` 复用此目录的 `stream.py`，各自持有独立发布实例。状态解码、组目标覆盖、持续发送以及取消保持使用同一实现。

每个发布实例拥有独立的 `source`，每个控制帧递增 `seq`。`stamp_ms` 是本次发布时间，`obs_stamp_ms` 是本次用于构造控制帧的反馈采样时间。无论保持目标多久，每次续发都使用此次反馈的采样时间。相同采样的重复发布保留其观测时间。有效期 `ttl_ms` 使用公共控制流工具根据预期频率和驱动看门狗计算。

## 操作

卡片启动且尚无控制目标时，每收到一帧有效反馈，就把各臂的实测位姿和夹爪开口发给 `servo_eef`。两个移动动作都需要新鲜反馈，并通过 `arm` 选择驱动支持的 `left` 或 `right`。

### `move_to` 绝对位姿与夹爪开口

用 `opening_m` 指定夹爪的绝对开口宽度，单位为米，范围由所选臂的驱动声明。例如，将左夹爪开到 30 毫米可单独调用：

```json
{"action":"move_to","arm":"left","opening_m":0.030}
```

设定 TCP 位姿时，填写完整的位置 `x_m`、`y_m`、`z_m`（米）和姿态 `qx`、`qy`、`qz`、`qw`（单位四元数）。参考系由下游驱动声明，TRON2 上为 `base_Link`。同时填写位姿和开口时，它们在同一帧中发布。只填写其中一项时，另一项随最新实测值发送。任一目标无效时，整条请求返回错误，并保留原目标。

```json
{"action":"move_to","arm":"left","x_m":0.50,"y_m":0.20,"z_m":0.30,"qx":0,"qy":0,"qz":0,"qw":1,"opening_m":0.030}
```

### `move_by` 相对移动

填写要改变的分量。

| 字段 | 从当前实测状态出发的增量 |
| --- | --- |
| `dx_m`、`dy_m`、`dz_m` | 沿驱动参考系 X、Y、Z 轴平移，单位 m。TRON2 上的正向分别为前、左、上。 |
| `rx_rad`、`ry_rad`、`rz_rad` | 以当前 TCP 为中心、沿基座轴表达的旋转向量，向量长度为转角，单位 rad。 |
| `opening_delta_m` | 夹爪开口变化，单位 m。正值张开，负值闭合。 |

例如，`{"action":"move_by","arm":"left","opening_delta_m":0.016}` 请求在当前实测开口上张开 16 mm。若当前开口为 80 mm、描述符上限为 85 mm，本卡记录和持续发送的目标都是 85 mm。平移超出工作空间时，取当前点到请求点的线段与边界的第一个交点。旋转增量独立施加在选定 TCP 上。若读入的保持值超出硬限位，驱动可拒绝该控制帧。

### 回执与保持

`move_to` 和 `move_by` 返回的 `status: published` 表示本卡已发布目标帧。用 `info.sample` 查看驱动反馈的实际位姿和夹爪开口。

使用双臂驱动时，首次选定一只手，卡片会读入另一只手的 TCP 位姿和夹爪开口，将这两组值固定在后续控制帧中。同一只手连续执行位移、转动或开合时沿用此基准。选中手的受控组保持目标，选中手其余分组取最新实测值。切换手臂时，卡片从当时的实测反馈读取新的保持基准。重复的新鲜观测也触发发布。后续 `move_by` 从下令时的实测值重新计算相对目标。

选择 `cancel` 会立即把受控组固定在最新实测位置，另一只手继续保持原来读入的位姿和开口。运动中断和全局中断也执行 `cancel`。`stop` 关闭卡片、清除目标并释放话题连接。

反馈中断期间暂停发布。此时执行 `cancel` 仍会清除旧目标。若尚无新鲜实测，取消会返回 `waiting_for_state`，第一帧恢复的新鲜反馈将成为保持目标。反馈恢复时仍有有效目标则重新按本次实测构造控制帧。

卡片在两帧采样时间推进的连续反馈中，若测得未选臂 TCP 离开保持基准超过 10 毫米或 5 度，就停止发布整条控制流。`info.fault` 给出侧别、实测位置偏差与角度偏差。新的测量仍可通过 `info.sample` 查看。停止并重新启动卡片后重新采集保持基准。

`info.sample` 是最新实测帧，`info.last.command` 是最近一次尝试发布的指令，`info.last.status` 是发布结果。`info.last.state_stamp_ms` 保留本次目标的起始观测时间。`info.last.publish_count` 是该目标成功发布的帧数。
