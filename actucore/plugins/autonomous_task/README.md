# autonomous_task

这张 ActuCore 卡片接收自然语言桌面操作任务。每轮从已连接的相机获取一组新 RGB，读取位姿、夹爪状态与历史回执，请求多模态模型选择一个动作。模型宣告完成后，卡片等待 3 秒，重新采集图像，并让同一模型在没有动作工具的情况下复核。复核可以确认完成、说明失败原因，或要求继续观察与纠正。

## 接线与配置

三个 `image/jpeg` 输入口分别为头部、左腕、右腕。任一路都可省略，执行视觉任务至少要接一路。卡片只在决策和复核时取图。已接入的每一路都必须在本轮提供新的 JPEG。TRON2 的 `camera`、`camera_left`、`camera_right` 可直接连接。其他安装方式可用上游声明的相机 ID 或配置项 `head_topic`、`left_wrist_topic`、`right_wrist_topic` 将已连接的话题映射到物理位置。

模型看不清局部时，可以通过 `observe` 指定原图区域。下一轮会同时提供带有来源帧编号的原分辨率裁剪和新采集的全景。每次最多查看两个视角，每项任务最多请求四次裁剪。

在卡片配置中填写 `base_url`、`key`、`model_name`。服务需提供支持图像与函数调用的 Responses API。`arm_mode` 默认为 `left`，也可选 `right` 或 `both`。设置通过画布保存，或在部署环境的 ActuCore YAML 中提供。仅在需要留存实验图像时设置卡片 YAML 的 `record_dir`，卡片按任务分别写入模型实际看到的 JPEG、逐步反馈和终态。

## 调用

启动画布后，上层通过 MCP 工具 `autonomous_task` 提交任务。下例是该工具的 `arguments`。

```json
{"action":"submit","instruction":"把胶带抓起来，向左移动约 5 厘米，再放下","arm_mode":"left","request_id":"tape-transfer-01"}
```

提交返回 `action_id`。用 `{"action":"status","action_id":"…","include_history":true}` 获取执行阶段、模型动作、SDK 回执和最终原因。用 `{"action":"cancel","action_id":"…"}` 停止后续决策。卡片会等待已经下发的动作结束。一次只接受一个任务。在同一进程保留的最近 32 个任务内，相同 `request_id`、指令和模式可重复查询。上层也可以按 ActuCore 的 ACP 契约接收完成事件。

模型请求超时或网关暂时不可用时，卡片保留动作历史，重新读取相机与状态后再推理，连续三次未收到有效响应会返回失败。如果 SDK 命令的执行结果未知，卡片会给出具体原因并结束当前任务。

## 实机执行

TRON2 的相机通过上游卡片接入。卡片内的 `tron2.py` 直接使用厂商 SDK 协议执行手臂与夹爪动作。部署 YAML 可通过 `vendor_url` 指定厂商服务地址，通过 `urdf_path` 指定与实机匹配的 URDF 文件。

每只启用的手臂提供 `move_to`、`move_by` 和 `set_gripper`。双臂模式也逐步串行执行。TRON2 使用基座坐标系，位置以米计，绝对姿态采用 xyzw 单位四元数，相对旋转采用基座系旋转向量（弧度），夹爪开口以毫米计。末端参考点沿用 v1 的 `grasper_L_Link` 或 `grasper_R_Link` 原点。观测还提供基座系下的手指延伸方向和开合轴。

模型指定末端位姿后，卡片使用当前关节状态计算 IK，检查关节限位、单步幅度，并用 MoveJ 执行。单步平移上限为 10 厘米，旋转上限为 30 度。MoveJ 执行关节插值，末端路径可能弯曲。夹爪按照模型请求的名义开口操作。接触物体时，实际开口可能大于请求值。

动作得到 SDK 确认且反馈稳定后，卡片读取新的相机画面和实测状态，再交给模型决策。回执中的 `completion_basis` 记录动作结束的依据。`target` 记录模型给出的运动目标，`actual` 记录实测反馈。模型根据物体与夹爪的实际位置决定是否需要修正。可见抓取位置合适时，模型可试夹并小幅提起，通过物体是否随夹爪离开支撑面判断抓持效果，空夹后可以重新张开、定位和试抓。

最终视觉复核使用本次任务的初始和当前图像，以及与夹爪收紧、末端达到最高位置、水平位移最大和随后张开对应的历史帧。模型据此确认物体是否随夹爪搬运，是否在释放后独立放稳。卡片同时提供根据实测末端位置计算的位移，便于核对用户要求的大致移动距离。

两个 `data/json` 输出话题为 `/actucore/autonomous_task/arm` 和 `/actucore/autonomous_task/gripper`，使用 `std_msgs/String`。每个已确认下发的动作发布一次，包含 `action_id`、`step`、`tool`、`arguments` 和实测 `feedback`。当前由内部适配器负责实际执行；未来接入下游执行卡片时，可在该边界替换适配器。
