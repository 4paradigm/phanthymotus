# 个人记忆管理

默认关闭。关闭时保留原有 prompt、记忆工具、技能、历史、后台代理和设备功能。开启后沿用原有系统规则和机器人身份，自动加载只负责信息库管理的内置 personal-memory 技能；不默认切换咨询角色或发起问卷。现有人脸或声纹任一已绑定身份匹配即可自动解锁，无手机确认。

## 数据存放与边界

用户、绑定、记忆和对话存储在机器人本地 `DB_PATH` 指定的 SQLite（默认 `agent-core/resource/data.db`）的 `pm_*` 表中。旧 `chat_*`、子代理结论和 `prompt_memory.md` 不迁移、不删除，也不注入个人模式，避免历史个人内容被当成公共知识。

本地存储不等于内容不出设备：使用云端模型时，对话、必要历史和相关记忆仍随请求发送到模型服务。完全离线需要本地模型。没有新增数据库加密；主机/容器管理员、持有 ACCESS_TOKEN 的运营者和配置的模型提供方属于可信边界。

按用户选择接受生物识别误匹配、照片/录音/合成声音冒用的风险；没有活体或防重放保证，相似度不是身份概率。不根据生物特征进行心理诊断或秘密画像；涉及心理分析时遵循明确授权和不确定性标注规则。

## 从 decision_core 卡片启用

1. 先配置部署 `.env` 的 `ACCESS_TOKEN` 并重启。个人模式和管理 API 要求认证；运营者 token 不提供给普通用户。
2. 在画布中连接 `ASR 输出 → decision_core 输入`；需要刷脸识别时再连接 `人脸识别输出 → decision_core 输入`。声纹模块随 ASR 工作，不需要重复连接声纹数据。
3. 从 `decision_core` 向本机 `TTS` 建立执行连线，并保留 TTS 到扬声器的原有音频链路。
4. 停止智能控制，打开 `decision_core` 的配置，开启「个人记忆（人脸或声纹自动识别）」并保存。无需填写 topic 或工具名。卡片配置窗口会显示当前模式和是否待下次启动生效。
5. 再开始智能控制，无需重启 AgentCore。启动流程从上游卡片实时 info() 取得实际 topic，从执行连线取得本机 TTS 工具，自动写入个人记忆路由。未连接 ASR/TTS 会明确报错并回滚启动。
6. 按下面的运营者 API 建档，绑定已经登记的人脸/声纹 ID。之后说话时自动识别、检索和记忆。`remember` 默认 false，只有用户同意长期保存时设为 true；`onboarding` 仅记录用户接受可选偏好问题的意愿，不自动启动问卷。

开关在智能控制运行期间固定，保存只修改下次启动配置；不会在对话中途切换权限。下次启动会等待旧轮次结束，关闭旧后台代理，清空内存中的会话、事件队列、原始输入缓存和身份依据，再重建工具及后台任务。个人数据库保留；关闭个人模式后恢复普通历史，不加载个人会话。旧轮次未能及时结束或连线校验失败时启动失败并保持停止。修改画布连线也只需停止后重新开始智能控制，路由会重新计算。

看到人只更新新鲜身份依据，不自行发起对话；ASR 到达时优先用声纹，或最近单人人脸证据。远程聊天不能借用摄像头在场身份，跨机器人执行连线不会自动授权为本机 TTS。

建议在感知配置中关闭陌生人 auto_enroll，并在同意后注册；本分支不改原有感知默认值。多路感知应使用同一组各自共享身份库的实例，更换模型或替换身份库后先解除旧绑定并重新登记。

此前通过 Python 写入 `personal_memory` 的配置仍兼容。只有使用卡片开关后，才设置 `use_canvas_routes=true` 改由画布自动管理来源和输出；不需要重复手填这些字段。

## 运营者 API

前缀 `/api/personal-memory`，请求头 `Authorization: Bearer <ACCESS_TOKEN>`。

| 操作 | 方法和路径 | 请求体 |
|---|---|---|
| 建档 | POST `/users` | `{"name":"小王","remember":true,"onboarding":true}` |
| 用户列表 | GET `/users` | 无 |
| 绑定人脸 | POST `/users/{user_id}/bindings` | `{"modality":"face","external_id":"p-3"}` |
| 绑定声纹 | POST `/users/{user_id}/bindings` | `{"modality":"voice","external_id":"p-8"}` |
| 解除绑定 | DELETE `/bindings/{modality}/{external_id}` | 无 |
| 记忆/问答偏好 | PUT `/users/{user_id}/preferences` | `{"remember":false,"onboarding":false}` |
| 删除用户及关联数据 | DELETE `/users/{user_id}` | 无 |
| 公共候选列表 | GET `/public-candidates` | 无 |
| 批准公共知识 | POST `/public-candidates/{id}/approve` | 无 |
| 删除公共候选/已批准条目 | DELETE `/public-candidates/{id}` | 无 |

face:p-3 和 voice:p-3 不自动关联；只有明确绑定同一个 user_id 才属于同一用户。已有绑定不能直接转移到别人。

## 会话和记忆

- 任一已绑定身份匹配后，本人的全部个人记忆都可检索。默认注入最新20条结构化记忆，其余通过 `memory_recall(query, limit, offset)` 分页查询，避免一次塞满上下文。
- 语音到达时固定身份，再排队；排队期间出现的另一张脸不会重新归属旧语音。每轮加载对应用户独立近期历史，清空旧摘要。未知、未绑定、多人或模态冲突时作为访客，不继承上一用户，不保存访客历史。重启后也等待新匹配。
- `remember_personal` 区分 fact（自述）、preference、event、analysis（待核实假设），并绑定当前来源 turn。可用 `forget_personal` 删除错误记忆，再保存更正。第三人的描述只归当前用户，不能写入第三人档案。
- 已识别但不保存长期记忆的用户，仍可在当前连续会话中使用最多18轮的临时上下文，只留内存；换人或下次进入时距离上轮超过5分钟则清除。访客不保留跨轮历史。
- 问题可跳过，也可选择自由聊天；记忆中的分析不是疾病或人格定论。敏感内容应先确认保存意愿。
- 暂停用 `set_memory_collection(false)`：保留既有资料，停止当前轮和后续记录；恢复需用户明确选择 `set_memory_collection(true)`。暂停时仍可查看、导出和删除。
- `set_memory_preferences(false, false, confirmed=true)` 是删除式关闭：清除私有记忆、对话和未公开候选；已经人工批准的通用知识需单独撤回。不要把“暂停记录”误当成这种删除。
- `propose_public_memory` 只提交通用知识候选，运营者审核无个人内容后批准；模型不能直接公开私人对话。语义审查由运营者负责。
- 不写旧共享历史，不生成共享个人对话日报，不自动吸收旁听内容。

## 内置技能与用户管理权

技能文件位于应用源码的 `builtin_skills/personal-memory/SKILL.md`，随镜像发布，不需要用户另行安装。只在个人记忆模式开启后作为必需技能加载；关闭模式时不注入它，也不注册个人资料工具。本技能仅负责记忆管理，不定义心理咨询角色，不默认主动提问。

开关只启用能力，不替用户同意保存。建档默认 remember=false，授权后记录；用户可跳过问答、暂停记录和撤回授权。内置技能规定个人信息分流、事实与假设区分、来源与去重、公共候选审核和数据管理流程；语义判断和理解用户意愿仍依赖模型，后端强制执行归属、分页范围、授权状态和写入权限。

用户可通过自然语言提出以下请求，由 agent 调用本人范围内的工具：

| 用户表达示例 | 工具及行为 |
|---|---|
| “你记住了我什么？” | export_personal_data，选择 memories；只看本人 |
| “把我的资料导出来” | 按 profile/memories/conversations/public_contributions/bindings 分页输出 JSON，next_offset 表示下一页；没有自动生成下载文件 |
| “这次别记录，保留之前的资料” | set_memory_collection(false)，暂停而不清空 |
| “恢复记录” | set_memory_collection(true)，需要明确选择 |
| “这条习惯记错了” | correct_personal，说明影响并确认后更正 |
| “忘掉这一条” | forget_personal，说明影响并确认后删除 |
| “撤回我提供的公共知识” | withdraw_public_memory，仅能撤回本人贡献，含已批准条目 |
| “清空资料，但保留识别身份” | delete_personal_data(false, confirmed=true)，清空记忆、历史和本人公共贡献并停止保存 |
| “删除我的档案并解除关联” | delete_personal_data(true, confirmed=true)，再删除用户与 face/voice 绑定，之后匹配为未绑定访客 |

**更正或单条删除会同时清空该用户的全部原始对话历史和未公开公共候选，以避免旧信息从复述、上下文中重新出现；其他结构化记忆保留。** 技能必须先说明这个范围并取得用户确认，工具 confirmed 默认 false，不确认不执行。若用户不接受这个范围，不应宣称已完成操作。

资料更改会更新版本；当前运行的旧上下文失效，下一次模型请求重新构建且不重新保存管理轮。等待语音/动作屏障后会再次检查版本，防止撤回期间排队的旧输出继续派发。数据库写入把版本与保存授权作为同一条 SQL 的条件，避免删除/暂停后的并发旧写入复活数据。

应用注销只删除身份关联，不删除 perception 内人脸/声纹模板、代表录音、访问记录或驱动日志。这些数据需通过对应模块另外处理。逻辑删除不等于磁盘安全擦除，离线备份和已发送模型请求也不能由此撤回。运营者/主机管理员访问边界仍与前文一致。

## 与原功能的关系

默认关闭，旧路径不变，独立 worktree 不修改原分支和线上部署。

开启时暂不向当前会话开放共享任务、后台子代理、任意文件/Shell/Python、跨机器人委派、原始传感器历史、旧共享记忆工具及其他已安装技能（内置 personal-memory 必需技能除外）。只开放个人记忆工具、finish 和配置的本机输出工具，实际派发也校验权限。原有设备安全/停止通路保留。

这是可切换的个人记忆管理功能，保留原有身份与业务提示；现有工具权限边界仍生效，尚未对所有旧工具完成多用户改造。需要完整常规机器人功能时，停止智能控制、关闭个人记忆，再启动智能控制。output_tools 只加入经审核的本机输出工具；加入任意读取、跨设备转发工具会扩大信任边界。

本模式不向共享 `/decision_core` DDS topic 广播个人决策或工具结果；停止写 LLM 请求/回复 JSONL、HTTP 请求体调试文件和主循环请求快照，性能日志去掉触发文本和 metadata。运营者仪表盘仍显示活动；perception 原有的原始音频、声纹样本、访问记录及驱动日志仍由原模块管理，部署方需单独制定保留规则。

## 测试、删除与回退

在开发环境 `cd agent-core && python -m pytest -q`。自动测试不使用真实模型、摄像头或麦克风；上线前仍需真机校准误接受/误拒绝、噪声、短语音、遮挡、多人切换、TTS回声和输出绑定。

删除是逻辑删除，不保证磁盘取证不可恢复。离线备份不会随在线删除改写，恢复备份时需重新应用删除记录。

回退：停止智能控制，在 decision_core 卡片关闭个人记忆，保存后再启动智能控制即可，无需重启 AgentCore。旧表和旧长期记忆仍保留；不要将未经分类的 pm_* 内容导入共享 prompt。
