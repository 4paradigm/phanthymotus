# 语音自声与第三人误接入修复

## 现场证据与范围

- 天轶部署 d5064f42 后，Jev 已开启、ASR 为 VAD。实际诊断显示语音得到较高 addressed 后进入 steer；Core 日志中主模型随后才识别为自播报回声。排除仅看板显示或开关未开的解释。
- 用户确认与第三人交谈也被 steer。当前判断只提供整段历史和宽泛的 addressed 问题，没有独立核验说话来源/收件人；不能用调高 route 阈值修复接入错误。
- 只改 Core，保持 Jev 默认关闭和原权限、消息路由契约。不开启控制、不播放、不替换运行中的服务；不把软件门禁当作声学 AEC。

## 实施

1. 从真实本机 MCP 播报调用记录有界、短期的文本参考，覆盖普通工具及系统 Hook；非播报、远程 peer、失败调用不得伪装成已播出的事实。参考只表示下发/可能播放，不代表物理播放确认。
2. 接入前匹配近期播报：只拒绝高度覆盖的连续回声片段，不因机器人忙碌一律屏蔽，不拒绝含额外人声指令的混合文本；短口令仍交给语义判断。窗口过期不使用参考。
3. 在同一次 Jev 请求增加发言来源/对象 Choice：human_to_robot、robot_echo、human_to_other、uncertain。必须明确判为 human_to_robot 且通过接入阈值，才使用路由结果；缺失、无效、冲突或不确定时拒绝语音。文字沿用原路由，不需要此判断。身份与上下文辅助解析称呼，不硬编码某个人名字。
4. 给 Jev 显式的近期播报参考与否定例，保留完整身份与主 Loop 历史；诊断记录拒绝原因，不记录逐字稿。
5. 测试回声片段/ASR 错字、混合口令、过期、短句、失败调用及非播报路径；独立验证第三人/不确定/无效返回不能到达 collector。用非敏感合成样例验证真实 Jev，模型结果单独报告，不将 mock 当准确率。

## 验收边界
