# 遥操 PR 的 bot 审查修复

## 目标与边界

按主仓 #259 和 Driver #321 的实际 bot 构建、测试与审查结果修复，重复提交并请求 review，直至两个最新 HEAD 均无未解决意见。保留 #259，已关闭的 #261 不再使用。只做本地开发、隔离验证及已授权的 PR 更新，不连接机器人、不修改运行服务，也不把镜像构建当作真机验收。

## 本轮问题与实施

1. Driver 标准 bot 构建的导入检查无法找到 `audio_msgs`；核查基镜像已有 overlay，优先复用并正确 source，不重复打包依赖；增加真实脚本的隔离检查。
2. CPU ActuCore 缺少标准部署片段；补齐不要求 GPU 的部署契约，说明其完整遥操隔离验证用途及镜像成本。
3. Core 的 12 项打断回归因测试 patch 解析为 `Event` 实例而失败；核验实际模块后修正测试定位，保留生产语义。
4. G1 原始碰撞网格不应纳入 Git；改为固定来源、SHA256 校验的显式构建前下载，保留模型与许可证，不允许在控制循环内联网或缺模型时跳过碰撞。
5. 按用户确认，不改 bot 和现有构建脚本、不要求特殊开关：标准 JP6.1 镜像自动包含遥操依赖，JP5.1.1 保持原兼容范围。卡片默认关闭，不因镜像包含依赖而启用硬件。通过 Dockerfile 的实际构建分支及 bot 常规构建验证。
6. 核查 Android 固定 Git 依赖的完整性记录和基础设施变更说明，处理 bot 的建议而不捏造镜像尺寸或运行验证。
7. 缺少站点 TLS、状态目录、标定或管理密钥时，不注册不可操作的遥操工具，保留明确配置诊断并确保 VLA 正常；不自动生成或迁移现场安全资料。
8. 测试区分天轶依赖、G1 专用 CasADi ABI 和跨仓 Driver：无相应可选环境时明确报告 skip，错误配置必须失败；完整天轶链路另用真实配套 Driver 源码运行，不以 skip 代替覆盖。

## 验证与迭代

- 分别执行受影响的 Core 测试、ActuCore 构建/下载契约与数值回归、Driver 构建上下文检查。
- 下载必须核对实际字节哈希；缺失、篡改、下载失败均保留明确错误，不向运行路径发布半成品。
- 代码、测试与相关说明同仓范围化提交；同步 PR 描述，向新 HEAD 申请 bot 构建与审查，逐条记录结果。
- 完成依据是两个最新 HEAD 的 bot 结果，以及所有实际意见的处理证据；旧 HEAD 通过、仅申请 review、跳过测试或未收到回执均不算完成。
