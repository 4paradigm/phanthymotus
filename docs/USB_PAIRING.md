# 手套接收器与 L20 Lite USB 网页配对

Core 的画布卡片会在所属 Driver 声明 `usb_pairing` MCP 工具时显示
**USB 设备配对**按钮。没有该能力的旧驱动不显示入口。

向导按顺序调用 Driver：

1. `begin`：操作者先退出遥操、停止动作，拔下接收器与灵巧手转接器。
   Driver 记录其他串口的基线，停止预览并清除本次标定。
2. `receiver`：只插一个无线接收器，Driver 用新增 USB 路径确定角色，
   不向接收器发送 Modbus 探测。此时手套可以未开机。
3. `hands`：保持接收器连接，再插入已供电的灵巧手转接器。
   Driver 仅对新增的手部候选设备做只读地址探测，确认左右手。
4. `apply`：复核并持久保存映射，在 Driver 内立即应用。
   Core 不写宿主机设备文件、不接收手填路径，也不自动启用运动。

所有有状态步骤携带 Driver 返回的 `session_id`；取消调用 `cancel`。
错误在当前步骤显示，不推进。会话闲置 10 分钟过期。
配对期间其他设备操作被 Driver 拒绝；正在动作、遥操或尚未完成卸力时不能开始。

完成后按原流程启动预览、标定、显式 arm。配对不会更改预览保护开关。
相同 CH340 转接器缺少唯一序列号时按物理 USB 路径保存；更换插孔或
扩展坞拓扑后需要重新配对，不承诺任意换口识别或自动恢复运动。

测试：先在仓库根目录运行 `npm ci` 安装锁定的测试依赖，再运行 `npm test`。
真机验收需按页面步骤实际拔插、保存，检查预览及重启恢复；不得把模拟测试当作硬件验收。
