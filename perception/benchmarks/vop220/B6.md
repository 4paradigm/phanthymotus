# B6 VOP deployment

B6 replaces the default 144-class YOLOE-26s segmentation bundle with a frozen
220-class YOLOE-26m detector. Its fused inference graph has 21,080,796
parameters and uses fixed 640 x 640 FP16 input. Runtime model files are
distributed through [ModelScope](https://www.modelscope.ai/models/ZhuojuLi/vop-b6-coverage20-20261111).
The downloader pins each target's engine and vocabulary by byte size and SHA256.
The public release revision is `d0478bfa17caab7f2dc573a819341a16c4a9ad95`.

The engine declares `detection_layout: yolo_dense_v1` in its JSON metadata.
Its `1 x 224 x 8400` output contains four xywh channels and 220 class scores.
The decoder selects one class per anchor, runs class-aware NMS at IoU 0.7
before clipping to the source image, and returns at most 300 objects. The
default confidence is 0.35. Both photo recognition and ROS2 streaming pass the
engine metadata to the decoder. Existing saved model aliases resolve to B6.

B6 starts from B5's fixed 70/30 interpolation and adds a classification branch
trained for 20 classes with reviewed positives, verified negatives, and old-data
replay. The deployment graph fuses that branch; it requires no new device-side
training library. Other vision engines retain their existing decoder.

## Validation

Both JP families completed Orin GPU inference on 107 development images,
MCP photo recognition, ROS2 start/stop, cold downloads, cached restarts,
and three independent services handling 360 requests with zero failures per
family. Local development F1 at IoU 0.7 was 46.986% on JP6 and 47.132% on JP5.
Those tests used an existing runtime image plus the verified source. A fresh
full dependency image rebuild remains for PR CI.

The submitter reported the following JP6 leaderboard results on 227 cases and
confirmed B6 for product PR submission:

| Version | F1 | FPS | Failed requests |
| --- | ---: | ---: | ---: |
| B4 | 47.04% | 1.3124 | 1.76% |
| B5 | 47.13% | 0.8671 | 3.08% |
| B6 | 47.15% | 0.6486 | 4.41% |

The F1 increment over B5 is small, while measured throughput and request
reliability declined. These are reported platform results, separate from the
local development scores. The device checks do not establish ten-instance
capacity or a GPU utilization limit under every workload.
